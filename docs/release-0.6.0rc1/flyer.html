Context-Fabric 0.6.0rc1

The Text-Fabric API on a new Rust core: same answers, a fraction of the memory, several times faster.

Context-Fabric reads Text-Fabric corpora and keeps the Text-Fabric Python API (F, E, L, T, S, N, C). In 0.6 the engine is rewritten in Rust and serves every query from a compiled, memory-mapped cache, so loading is nearly instant and memory stays small.

What you get

  • Drop-in API. Existing Text-Fabric scripts run unchanged: the same calls, arguments and return values for the core functions.
  • Same answers. Checked against Text-Fabric 13.0.19 on three corpora: about 505,000 value checks, the 34-query search suite, and recorded reference outputs.
  • Small, shared memory. The corpus stays memory-mapped, so worker processes share one copy. Four BHSA workers use 642 MB, where Text-Fabric uses 25 GB.
  • Safe search. Results stream lazily, runaway searches stop at Text-Fabric's result cap, Ctrl-C interrupts a running search, and a bad template raises a clear SearchTemplateError.
  • Light install. No required dependencies. Optional extras: [numpy] for array output, [download] for fetching corpora.

Good to know. The first load compiles the corpus into a cache (about 29 s and 614 MB on disk for BHSA); every later load reuses it. Caches from 0.5 are not read; they are rebuilt automatically. L.u (0.13 vs 0.11 µs) and a full N.walk() are slightly slower than Text-Fabric. A short list of deliberate differences, such as tuples instead of arrays for some row data, is in the changelog. This is a release candidate: please report anything that differs from Text-Fabric.
